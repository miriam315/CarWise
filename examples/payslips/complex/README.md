# תלושים מורכבים ופיקטיביים לבדיקת CarWise

אלה דוגמאות דמויות תלוש ישראלי, לא עיצוב מותאם למחלץ הקיים: טבלאות צפופות במספר עמודות, קודי רכיבים, כמויות ותעריפים, תשלומים וניכויים מקבילים, ברוטו לתשלום מול ברוטו למס ולפנסיה, הפרשות עובד ומעסיק, יתרות חופשה ומחלה, נתונים חודשיים ומצטברים ונוכחות.

החבילה מכילה שלושה תרחישים, כל אחד ב־PDF עם שכבת טקסט, PDF סרוק עם הטיה קלה, PNG ו־JPEG — 12 קובצי תלוש. העימוד משתנה בין התרחישים: בתלוש המכירות הוחלפו מיקומי טבלאות התשלומים והניכויים. בתלוש השעתי קיימים כמות שעות ותעריף, בנוסף לסכום רכיב השכר.

| תרחיש | שכר בסיס | עמלות | בונוס | פנסיית עובד | קרן השתלמות עובד | נקודות זיכוי | השתתפות ברכב |
|---|---:|---:|---:|---:|---:|---:|---:|
| 01-complex-monthly | 19,000.25 | 1,000 | 0 | 6% | 2.5% | 2.25 | 350 |
| 02-complex-sales | 12,500 | 3,250.75 | 1,500 | 6.5% | 2.5% | 2.75 | 0 |
| 03-complex-hourly | 14,364 | 0 | 750 | 6% | 2.5% | 3.25 | 650 |

`expected-values.json` מכיל את הנתונים הידועים של התרחיש, ולא פלט של המערכת. במקרה השעתי סכום שכר היסוד מופיע בטבלה: 168 שעות כפול 85.50. השעות הנוספות, הנסיעות והזקיפות אינן שכר בסיס. אין להסיק את השכר מסך הברוטו או את שיעור העובד מסכום הניכוי.

## תוצאת הבדיקה בפועל

ב־21 באוקטובר 2026 נבדקו מחדש כל 12 הקבצים המקוריים במנוע החילוץ המבודד ששופר, בעברית ואנגלית ובסף ביטחון 75. **84 מתוך 84 השדות תאמו לנתוני האמת — ללא שדות חסרים או שגויים.** זמני החילוץ היו כ־1–12 שניות לקובץ בהרצה זו. קובצי התלושים עצמם לא שונו כדי להתאים למחלץ.

בבדיקה הקודמת, ב־20 באוקטובר, כל השדות נשארו ריקים. התוצאה ההיסטורית המקורית שב־`verified-results.json` בתוך ה־ZIP נשמרת כפי שהייתה. הראיות החדשות נמצאות ב־[דוח הבדיקה המעודכן](../../../docs/complex-payslip-verification-2026-10-21.md) ובקובץ JSON הצמוד אליו; הוא כולל גם את גיבוב חבילת המקור.

המחלץ החדש משתמש בכותרות העמודות ובמיקום התאים, בקריאות OCR משלימות ובעיבוד ניגודיות מקומי. הבדיקה אינה הוכחת תמיכה בכל תלושי השכר האמיתיים. שדה עמום/סותר נשאר ריק ולא הופך לאפס, ותמיד נדרש אישור עובד מול המקור.

כל מסמך מסומן כפיקטיבי. אין פרטי אדם, חשבון בנק או מזהים אמיתיים. המס, הנטו, המצטברים והיתרות הם נתוני המחשה, ולא חישוב שכר מאומת או שחזור של תוכנת שכר מסוימת.

## שימוש

חלצו את קובץ ה־ZIP, פתחו עובד בדיקה במסך **הנתונים שלי**, והעלו קובץ אחד בכל פעם. השוו לתוצאות הצפויות. ערך חסר אינו אפס, ואין לאשר שדות שלא אומתו מול המקור. חילוץ לבדו אינו שומר נתונים; **שמירה וחישוב מחדש** משנה את פרופיל העובד.

לגבי שכר עם אגורות: הקוד העדכני כבר מגדיר `step=0.01`. נבדק בדפדפן ששכר 19,000.25 תקין, נשמר במסד וחוזר אחרי רענון. אם הדפדפן מציג דרישה למספר שלם, עצרו את השרת, הריצו `git pull origin main`, אחר כך `npm run ocr:setup`, `npm run build` ו־`npm start`, ובצעו רענון עם Ctrl+F5.

## יצירה מחדש

`scripts/generate-complex-payslips.py` יוצר את המסמכים ואת נתוני האמת ב־`.local/complex-payslips`. נדרשים Python עם ReportLab, PyMuPDF ו־Pillow וגופני DejaVu בנתיב Linux שבסקריפט. הסקריפט אינו משנה את המחלץ ואינו מבצע בדיקת חילוץ; תוצאות החילוץ בחבילה נמדדו בנפרד.

לבדיקת החבילה המקורית במנוע המעודכן הריצו `npm run ocr:verify:complex`. אין צורך ליצור מחדש מסמכים או להזין מפתח AI.
