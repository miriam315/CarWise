# חילוץ תלוש מקומי וצילום באתר

## התקנה חד־פעמית בשרת

החילוץ פועל בשרת CarWise בתוך סביבת האירוח של הארגון, ולא אצל ספק AI. אם השרת בענן, זהו עיבוד בענן של הארגון — לא במחשב העובד. אין צורך במפתח AI, ואין התקנה אצל כל עובד. השרת זקוק ל־Tesseract 5 ולכלי Poppler (`pdftotext`, `pdfinfo`, `pdftoppm`).

ב־Windows, אפשר להתקין דרך CMD:

```cmd
winget install --id UB-Mannheim.TesseractOCR --exact --source winget
winget install --id oschwartz10612.Poppler --exact --source winget
```

סגרו ופתחו CMD כדי לטעון את PATH המעודכן. אם הכלים הותקנו במיקום אחר, הגדירו את נתיבי ההפעלה במשתני השרת המפורטים בהמשך. Tesseract מזוהה גם בתיקיית ההתקנה הרגילה ב־Program Files.

ב־Debian/Ubuntu, מנהל השרת יכול להתקין:

```sh
sudo apt-get update
sudo apt-get install tesseract-ocr poppler-utils
```

בתיקיית הפרויקט, התקינו את קובצי השפה המקומיים:

```sh
npm run ocr:setup
npm run build
npm start
```

הסקריפט מוריד רק מודלי שפה של Tesseract בעברית ובאנגלית, מגרסה קבועה של `tesseract-ocr/tessdata_fast`, ומאמת SHA־256 לפני שמירה. הקבצים נשמרים ב־`.local/ocr/tessdata`, שאינה בגיט. אין הורדות בזמן העלאת תלוש. בשרת ללא אינטרנט אפשר להריץ את ההתקנה בסביבת בנייה ולהעתיק את הקבצים המאומתים לסביבת השרת. קובצי השפה מופצים בפרויקט המקור ברישיון Apache 2.0; יש לשמר את הודעות הרישיון בהפצה.

בניהול → **פרומפטים ותלושים**, הפעילו חילוץ ושמרו. מסך הזמינות יציין כלים או שפות חסרים; בדיקת ההתקנה נשמרת במטמון למשך עד 20 שניות. אפשר להפעיל OCR כשה־AI של השיחה כבוי. אין מעבר אוטומטי לספק חיצוני אם הכלים אינם זמינים.

נתיבי תשתית אופציונליים, במשתני סביבת השרת או בהגדרות האירוח:

| משתנה | שימוש |
|---|---|
| `CarWise__PayslipOcr__TesseractPath` | נתיב מלא לקובץ ההפעלה Tesseract |
| `CarWise__PayslipOcr__PdfToTextPath` | נתיב מלא ל־pdftotext |
| `CarWise__PayslipOcr__PdfInfoPath` | נתיב מלא ל־pdfinfo |
| `CarWise__PayslipOcr__PdfToPpmPath` | נתיב מלא ל־pdftoppm |
| `CarWise__PayslipOcr__TessdataDirectory` | תיקיית קובצי השפה; חשובה גם בפרסום השרת ללא תיקיית הפרויקט |

נתיבי קובצי ההפעלה אינם ניתנים לשינוי דרך אתר הניהול: שינוי שלהם מאפשר להריץ תוכנה בהרשאות השרת. בניהול ניתן להגדיר שפות (`heb+eng`, `heb`, `eng`), מגבלת עמודים 1–6, זמן כולל 10–120 שניות וסף ביטחון לזיהוי 50–100. ברירות המחדל: שלושה עמודים, 60 שניות וסף 75. אחוז הביטחון הוא מדד של מנוע הזיהוי, לא הבטחת דיוק.

## שימוש ושמירה

העובד פותח **הנתונים שלי** ובוחר PDF, PNG או JPEG עד 8MB, או לוחץ **צילום תלוש**. חלון הצילום כולל תצוגה מקדימה, צילום מחדש ואישור שימוש בצילום. הוא אינו מקליט או מעלה אוטומטית. המצלמה נעצרת בסגירה או ביציאה לחלון אחר. אם אין הרשאה למצלמה, אפשר לבחור תמונה או להשתמש בצילום דרך המכשיר. מצלמה בתוך האתר דורשת HTTPS או localhost ותמיכת הדפדפן. תמונות HEIC אינן נתמכות; יש לבחור JPEG/PNG.

לאחר אישור עיבוד מקומי ולחיצה על חילוץ:

1. PDF עם שכבת טקסט נקרא מקומית. כשלא זוהו בו שדות, העמודים מרונדרים מקומית ומועברים ל־OCR. תמונות וצילומים נקראים ישירות ב־OCR.
2. מזהים רק שורות בעלות תווית מפורשת וערך יחיד: שכר בסיס, עמלות, בונוס, אחוז פנסיית עובד, אחוז קרן השתלמות עובד, נקודות זיכוי והשתתפות ברכב. אין הסקת בסיס מברוטו, אחוזים מניכוי כספי או אפס משדה חסר. שורות עם מספרים מרובים, ערכים סותרים או זיהוי חלש נשארות לבדיקה ידנית.
3. לדפדפן חוזרים רק השדות ברשימה הסגורה והודעות קבועות. אסמכתאות נבנות משם שדה קבוע ומספר מאומת — לא מקטע טקסט מהתלוש. הטקסט הגולמי אינו נשלח ל־AI, לדפדפן או ל־DB.
4. העובד משווה למקור, מתקן ומסמן במפורש כל שדה לשימוש. לאחר העברה לטופס, לוחצים **שמירה וחישוב מחדש**. רק אז הערכים נשמרים בפרופיל השיחה ב־`carwise_conversations.employee`, דרך מנגנון השמירה הקיים של PostgreSQL/Supabase. הם נטענים מחדש בכניסה הבאה. שדות שלא סומנו אינם משנים את הערכים הקיימים. אין שינוי בסכומי ההשתתפות שאושרו על ידי נציג.

אין שמירת מסמך, תמונה או טקסט OCR לצורך חישוב. אין קריאת AI או רשומת חיוב AI עבור החילוץ המקומי. OCR אינו מכסה כל תבנית תלוש: טבלאות מורכבות עשויות לדרוש הזנה ידנית, ובכל מקרה נדרש אימות של החודש והשדות מול התלוש המקורי.

## תפעול ואבטחה

המסמך עובר לכלים דרך stdin/stdout, ללא כתיבת קובץ תלוש זמני על ידי היישום. תהליכי הכלים אינם מקבלים בירושה את סודות היישום. יש גבולות לגודל קלט ופלט, למספר עמודים, לממדי תמונה, לזמן כולל ולשני חילוצים מקבילים בתהליך השרת. מגבלת קצב ההעלאות נשארת פעילה ומשותפת ליכולות העלאה נוספות.

אין זו הבטחה למחיקת כל עותק בזיכרון או הגנה מלאה מפגיעות בכלי PDF/OCR. לפני פריסה אמיתית, יש לעדכן את הכלים ולהריצם בסביבה מבודדת עם מגבלות זיכרון/CPU, הרשאות מצומצמות, ללא גישה לרשת או לסודות וללא הקלטת קלט/פלט בניטור. יש להגן גם על שדות השכר הנשמרים ב־DB, על הגיבויים ועל גישת המנהלים. ראו [פרטיות תלושי שכר](payslip-privacy.md).

בדיקות הפיתוח משתמשות בתלושים סינתטיים בלבד: PDF טקסטואלי, PDF סרוק, PNG בעברית ו־JPEG; הן בודקות שאין פרטים מזהים בתוצאה, שאין שימוש ב־AI, וששדות מאושרים ומתוקנים נשמרים ב־DB ונטענים אחרי רענון. בדיקות מצלמה משתמשות בזרם וידאו סינתטי ובדחיית הרשאה מדומה, ולא במצלמה אמיתית. `scripts/smoke.py` דורש גם Pillow ו־ReportLab בסביבת הבדיקות.
