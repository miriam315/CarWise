# חילוץ תלוש במנוע מקומי מבודד וצילום באתר

## התקנה חד־פעמית בשרת

כל תלוש מעובד במכולת Linux חדשה ונפרדת, באמצעות Poppler ו־Tesseract. השרת אינו מפעיל את הכלים על מערכת ההפעלה שלו. אין קריאה לספק AI, ואין מעבר לעיבוד בלתי מבודד כשהמנוע אינו זמין. כאשר השרת בענן, העיבוד מתקיים בסביבת האירוח של הארגון ולא במחשב העובד.

נדרשים Docker עם מנוע Linux מקומי, Node.js 22.13+ או 24+ ו־.NET SDK של הפרויקט. ב־Windows התקינו Docker Desktop:

```cmd
winget install --id Docker.DockerDesktop --exact --source winget
```

פתחו Docker Desktop, השלימו את הגדרת WSL 2 אם תתבקשו, וודאו שנבחרו Linux containers. השרת חייב לפעול באותו מחשב שבו מנוע Docker; חיבור למנוע דרך TCP/SSH נדחה. בלינוקס העדיפו מנוע מקומי ייעודי במצב rootless, בהתאם למדיניות הארגון.

לפני ההתקנה הריצו `docker info` ב־CMD. אם מתקבלת שגיאת חיבור למנוע, יש לפתוח Docker Desktop ולהמתין שהוא מסיים לעלות; התקנת Docker לבדה אינה מפעילה את המנוע. אם מוצגת שגיאת WSL, יש להשלים את ההנחיה שמופיעה ב־Docker Desktop. סקריפטי ההתקנה והאימות עוצרים מראש ומציגים את שגיאת Docker המקורית. אין להריץ `ocr:verify` לפני ש־`ocr:setup` הסתיים בהצלחה.

מתיקיית הפרויקט:

```sh
npm run ocr:setup
npm run ocr:verify
npm run ocr:verify:complex
npm run build
npm start
```

ההתקנה דורשת אינטרנט: היא מורידה סביבת ריצה רשמית של .NET ומאמתת SHA־512 מול מטא־דאטה רשמי ב־HTTPS, מושכת Ubuntu 24.04 ומקבעת את digest הבסיס, ומתקינה כלים ושפות מחבילות Ubuntu חתומות. תמונת `carwise-ocr:1` נבנית מקומית. הקשר הבנייה מכיל רק את תוצרי פרויקט העובד וסביבת הריצה, ללא קוד השרת, מסדי נתונים, סודות או הגדרות היישום. תיעוד הגרסאות וה־digest נשמר ב־`.local/ocr-worker/build-info.json`, שאינו בגיט. אין הורדות או משיכת תמונות בזמן עיבוד תלוש.

בסביבת אירוח ללא אינטרנט, בנו ובדקו את התמונה בסביבת בנייה מאושרת באותה ארכיטקטורה, והעבירו אותה באמצעות `docker save` ו־`docker load`. בצעו בנייה מחודשת ועדכון מבוקר כדי לקבל תיקוני אבטחה; יש לבדוק מחדש את החילוץ לאחר עדכון כלים ושפות.

בניהול → **פרומפטים ותלושים**, הפעילו חילוץ ושמרו. בדיקת הזמינות נשמרת במטמון עד 20 שניות. ניתן להגדיר שפות (`heb+eng`, `heb`, `eng`), עמודים 1–6, זמן חילוץ 10–120 שניות וסף ביטחון 50–100. ברירות המחדל: 3 עמודים, 60 שניות וסף 75. במסלול עברי נעשה שימוש גם במודל האנגלי לקריאת ספרות; קריאה בעברית בלבד יכולה לשמש לתיקון תוויות מוכרות, בלי להחליף מספרים. אין צורך במודל, מפתח או פרומפט AI.

הגדרות תשתית בלבד, שאינן ניתנות לשינוי דרך אתר הניהול:

| משתנה | שימוש |
|---|---|
| `CarWise__PayslipOcr__DockerPath` | נתיב Docker CLI, ברירת מחדל `docker` |
| `CarWise__PayslipOcr__Image` | תמונה מקומית מאושרת, ברירת מחדל `carwise-ocr:1`; אפשר לקבע digest |

הגדרות נתיבי Tesseract/Poppler הישנות בשרת אינן משנות את העובד. אין אפשרות לכבות את הבידוד דרך הניהול.

## שימוש ושמירה

העובד פותח **הנתונים שלי** ובוחר PDF, PNG או JPEG עד 8MB, או לוחץ **צילום תלוש**. חלון הצילום כולל תצוגה מקדימה, צילום מחדש ואישור שימוש בצילום. הוא אינו מקליט או מעלה אוטומטית. המצלמה נעצרת בסגירה או ביציאה לחלון אחר. אם אין הרשאה למצלמה, אפשר לבחור תמונה או להשתמש בצילום דרך המכשיר. מצלמה בתוך האתר דורשת HTTPS או localhost ותמיכת הדפדפן. תמונות HEIC אינן נתמכות; יש לבחור JPEG/PNG.

אפשר גם לגרור קובץ אל אזור ההעלאה. בחירה, גרירה וצילום זמינים גם כשמנוע החילוץ כבוי או חסר; במקרה הזה מוצגת הודעת הזמינות ורק פעולת החילוץ חסומה. קובץ אחד עד 8MB מתקבל לאחר בדיקת חתימה בסיסית בדפדפן, בנוסף לבדיקות השרת.

לאחר הבחירה מוצג התלוש בתוך האתר. תמונה מוצגת מקומית באמצעות כתובת Blob, ו־PDF מצויר ל־canvas באמצעות PDF.js ו־worker המוגשים מהאתר עצמו, ללא שירות תצוגה חיצוני. קיימים הגדלה/הקטנה ומעבר בין עמודי PDF. אין הפעלת קישורים, טפסים או JavaScript מתוך המסמך. קריאת ה־PDF מוגבלת בזמן וברזולוציית תצוגה; מסמך פגום או מוגן בסיסמה מציג הודעה. זהו פענוח בדפדפן של העובד לצורך תצוגה, נפרד מבידוד ה־OCR בשרת; יש לשמור על דפדפן וספריית תצוגה מעודכנים.

התלוש נשאר מוצג גם אחרי חילוץ כדי לאפשר השוואה למקור. הסרה, החלפת קובץ או יציאה מהמסך משחררות את כתובת התמונה ואת עובד ה־PDF. החלפת קובץ מאפסת את אישור העיבוד ואת השדות המוצעים. אין כתיבה ל־localStorage/IndexedDB ואין העלאת המסמך לשרת לפני אישור מפורש ולחיצה על חילוץ.

לאחר אישור עיבוד מקומי ולחיצה על חילוץ:

1. PDF עם שכבת טקסט נקרא מקומית, כולל מיקומי המילים. כשלא זוהו בו שדות, העמודים מרונדרים מקומית ומועברים ל־OCR. תמונות וצילומים נקראים ב־OCR עם מספר שיטות חלוקה ועיבוד ניגודיות משלים לפי הצורך; כל הקריאות כפופות לזמן המסמך שהוגדר.
2. מזהים שורות פשוטות וגם תאים בטבלאות לפי תווית, מיקום וכותרת עמודה: שכר בסיס, עמלות, בונוס, אחוז פנסיית עובד, אחוז קרן השתלמות עובד, נקודות זיכוי והשתתפות ברכב. כמות ותעריף אינם סכום רכיב; עמודת מעסיק או מצטבר אינה שיעור עובד חודשי. אין הסקת בסיס מברוטו, אחוזים מניכוי כספי או אפס משדה חסר. תאים עם ערכים מרובים, סתירה או זיהוי חלש נשארים לבדיקה ידנית.
3. לדפדפן חוזרים רק השדות ברשימה הסגורה והודעות קבועות. מקטעי אסמכתה אינם מוחזרים מהעובד; השרת מחזיר רק מספרים ושמות שדות מוגדרים. הטקסט הגולמי אינו נשלח ל־AI, לדפדפן או ל־DB.
4. העובד משווה למקור, מתקן ומסמן במפורש כל שדה לשימוש. לאחר העברה לטופס, לוחצים **שמירה וחישוב מחדש**. רק אז הערכים נשמרים בפרופיל השיחה ב־`carwise_conversations.employee`, דרך מנגנון השמירה הקיים של PostgreSQL/Supabase. הם נטענים מחדש בכניסה הבאה. שדות שלא סומנו אינם משנים את הערכים הקיימים. אין שינוי בסכומי ההשתתפות שאושרו על ידי נציג.

אין שמירת מסמך, תמונה או טקסט OCR לצורך חישוב. אין קריאת AI או רשומת חיוב AI עבור החילוץ המקומי. במסך מוצג כמה שדות זוהו מתוך שבעה; שינוי ידני מציג גם את ההצעה המקורית. בדיקת 12 התלושים המורכבים המקוריים עברה עם 84/84 ערכים נכונים; ראו [ראיות וגבולות המדידה](complex-payslip-verification-2026-10-21.md). OCR אינו מכסה כל תבנית תלוש: טבלאות מורכבות עשויות לדרוש הזנה ידנית, ובכל מקרה נדרש אימות של החודש והשדות מול התלוש המקורי.

## תפעול ואבטחה

לפני שליחת המסמך, השרת יוצר מכולה ובודק את תצורתה בפועל דרך `docker inspect`. אם המדיניות אינה מתקיימת, המסמך אינו נשלח למכולה. התמונה נפתרת ל־ID בלתי משתנה לכל משימה. ההגבלות כוללות:

- ללא רשת (`network=none`), ללא מיפוי תיקיות שרת, סודות, מסד נתונים או Docker socket.
- משתמש 65532 ללא יכולות Linux, `no-new-privileges`, מערכת קבצים לקריאה בלבד ומרחבי תהליכים ו־IPC נפרדים.
- זיכרון 512MiB ללא swap נוסף, ליבה אחת, עד 64 תהליכים ו־128 קבצים פתוחים; core dumps כבויים.
- `/tmp` זמני בזיכרון עד 64MiB, עם `noexec/nosuid/nodev`. הוא נעלם עם המכולה. אין מנהל לוגים למכולה.
- קלט עד 8MiB, מגבלות עמודים/ממדים/פלט, שני חילוצים מקבילים וזמן מוגבל. השרת מסיר את המכולה גם בביטול בקשה; העובד מפסיק בעצמו בתוך 135 שניות אם השרת נסגר במהלך פעולה רגילה.

המסמך מועבר דרך stdin, והפרוטוקול החוזר מאפשר רק שבעה שדות מספריים בטווחים קבועים, סוג מקור וקודי שגיאה. טקסט חופשי, stderr ופירוט חריגות אינם מוחזרים לעובד או נרשמים בלוג היישום. שגיאת בידוד גורמת לעצירה ולהזנה ידנית, ללא ניסיון דרך AI או כלי מערכת מארחים.

`npm run ocr:verify` בודק את מסלול ההפעלה האמיתי: משתמש, היעדר יכולות, חסימת רשת, root לקריאה בלבד, היעדר קובצי יישום/socket/סודות, מגבלות cgroup ואי־שיתוף קבצים זמניים בין משימות. הבדיקה דורשת את התמונה המקומית. בדיקות `scripts/smoke.py` כוללות גם PDF טקסטואלי וסרוק, PNG בעברית, JPEG, בדיקת סקירה ושמירה ב־DB ומצלמה סינתטית. הן דורשות Pillow, ReportLab, Playwright ו־Chromium ומשתמשות בנתונים סינתטיים בלבד.

Docker חולק kernel עם המארח; זה אינו בידוד הרמטי או סריקת נוזקות. הרשאה ל־Docker CLI של השרת היא הרשאת תשתית משמעותית: יש להשתמש בשרת/מנוע ייעודי או rootless מאושר, לא לחשוף socket לעובד, ולעדכן מערכת הפעלה, Docker וכלי OCR. בסגירה חריגה של השרת ייתכן שתישאר מכולה שנוצרה אך טרם הופעלה; אפשר לאתר אותה באמצעות `docker ps -a --filter label=carwise.ocr.job=true`. יש להסיר משימות יתומות לאחר וידוא שאינן פעילות. יש להגביל גם העלאות ולוגים בפרוקסי, להגן על DB וגיבויים ולקבוע מדיניות שימור. ראו [פרטיות תלושי שכר](payslip-privacy.md).
