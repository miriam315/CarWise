## תוצאה שנמדדה

כל 12 הקבצים המקוריים שב־`examples/payslips/complex/CarWise-complex-demo-payslips.zip` נבדקו מחדש במנוע Docker המבודד, בלי שינוי בתלושים. **84 מתוך 84 השדות תאמו לנתוני האמת שבחבילה; לא חזרו ערכים שגויים או חסרים.** בהרצה זו נמדדו כ־1–12 שניות לקובץ, בסף ביטחון 75 ובמגבלת חילוץ 60 שניות.

זהו שיפור לעומת בדיקת 20 באוקטובר, שבה כל שבעת השדות נשארו ריקים בכל קובץ. זו ערכת בדיקה סינתטית קטנה, ולא מדידת דיוק של תלושים אמיתיים או הבטחת זמן לשרת ייצור. [תוצאות מפורטות, נתוני אמת וגיבוב החבילה](complex-payslip-verification-2026-10-21.json).

## מה השתנה בקוד

- `LocalPayrollLayout` קורא מיקום מילים מ־Poppler bbox ומ־Tesseract TSV. תווית רכיב וכותרות עמודות קובעות את תא הסכום; אין בחירה של המספר הראשון או האחרון בשורה.
- מופרדות טבלאות מקבילות באמצעות עמודות קוד ותיאור. נקודות זיכוי נקשרות לכותרת שמעליהן; שכר שעתי נקרא מעמודת הסכום, ללא הכפלת כמות בתעריף או החלפה בברוטו. אחוזי עובד נקראים רק מעמודת אחוז עובד, גם כשסימן `%` נמצא בכותרת ולא בתא.
- טקסט עברי חזותי/לוגי וסימוני כיווניות מנורמלים בלי להפוך ספרות. קו מפריד קטן אינו מפצל תווית לשתי שורות. תווית מצטברת/מעסיק אינה מתקצרת לתווית חודשית/עובד.
- ל־OCR יש קריאות משלימות למבנה עמוד, בלוק וטקסט דליל; אם עדיין חסר מידע מתבצעת קריאה עם סף ניגודיות מקומי אדפטיבי. העיבוד מסתיים מוקדם כשכל השדות זוהו, וכפוף למגבלת הזמן המשותפת של המסמך.
- מסלול עברית ייעודי יכול להחליף רק תווית עברית מוכרת שנקראה כאותיות לטיניות באותו מיקום. הוא **לעולם אינו מחליף מספר**. גם בהגדרת שפה `heb` המסלול המספרי משתמש באנגלית לצד העברית, כי מודל עברי בלבד עלול לשבש ספרות.
- כל שורת OCR שטוחה נבנית מחדש ממיקומי כל המילים. מזהה בלוק/שורה של Tesseract אינו מספיק: הוא עלול לפצל ״שכר בסיס, כמות 1, סכום 12,500״ למקטע מטעה ״שכר בסיס 1״.
- סתירה בין מקורות/קריאות נשארת ריקה גם אחרי מיזוג נוסף. לא מסיקים אחוז מניכוי כספי, אפס משדה חסר או נקודה עשרונית מסימן דומה. לכל הצעה נדרש עדיין אישור עובד.
- מסך הסקירה מציג מספר שדות שזוהו מתוך שבעה ואת הערך המקורי שהוצע כשעורכים שדה. רק השדות שאושרו מועברים לטופס; שמירה בפרופיל מתבצעת בפעולה הקיימת לאחר בדיקה.

תלוש וטקסט גולמי אינם נשלחים לספק AI, לדפדפן כתוצאת חילוץ או ל־DB. אין שינוי בהרשאות, בבידוד, במגבלות המשאבים או בפרוטוקול שבעת השדות המספריים. אין מיגרציית מסד חדשה.

## עדכון והרצה

עצרו את השרת ובצעו:

```sh
git pull origin main
npm run ocr:setup
npm run ocr:verify
npm run ocr:verify:complex
npm run build
npm start
```

בניית מנוע ה־OCR מחדש הכרחית; `npm run build` לבדו אינו מעדכן את קוד העובד שבתמונת Docker. נדרשת גישה לאינטרנט בעת התקנה/בנייה מלאה, ולא בעת חילוץ.

`ocr:verify:complex` פותח את החבילה המקורית, משווה כל ערך ל־`expected-values.json`, בודק כל 84 הערכים וכותב ראיות ל־`.local/complex-ocr-verification.json`. אין תלוש אמיתי או קריאת ספק בתהליך. בבדיקה כאן עודכן קוד העובד בשכבה מקומית על תמונת הבסיס שכבר נבדקה, משום שבנייה חדשה של חבילות Ubuntu נתקלה ב־DNS. הכלים וסביבת הריצה נשארו כפי שהיו; בדיקות הבידוד עברו על התמונה המעודכנת.

בדיקות יחידה נוספות מכסות עימוד הפוך, כמות/תעריף מול סכום, מעסיק/מצטבר, כותרת חסרה, עמוד אחר, ביטחון נמוך, סכום שלילי, פיצול שורות וסתירות. כל 212 בדיקות .NET עברו, כולל בדיקת 12 הקבצים ובידוד Docker בפועל. בדיקת הדפדפן כוללת גם חילוץ כל שבעת השדות מה־PDF הצפוף, מונה שדות, תיקון ידני, אישור מפורש ושמירת הנתון המתוקן במסד לאחר רענון.
