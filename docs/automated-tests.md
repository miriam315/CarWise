# בדיקות אוטומטיות

## הרצה רגילה במחשב (כולל Windows CMD)

```cmd
npm ci
npm test
npm run build
```

נדרשים Node.js 24 ו־.NET SDK 10. הפקודה `npm test` מריצה בדיקות מוכנות לענן ואת בדיקות השרת: חישובי שכר ונטו, זכאות, הרשאות, חשבונות וסיסמאות,
הגדרות, ניתוב AI ועלויות, החלפות רכבים, פרטיות ומעבדת החלטות.
היא אינה דורשת מפתחות Supabase או AI. בבדיקות שירותי צד שלישי נעשה שימוש
בתשובות מבוקרות; הן אינן בדיקת זמינות של הספק האמיתי.

בדיקות האינטגרציה של מנוע ה־OCR הקודם נשארו בדיקות היסטוריות אופציונליות ומדולגות בהרצה הרגילה. המנוע אינו מחובר למסלול התלושים הפעיל. אין צורך להתקינו לשימוש במערכת.

מסלול התלושים הנוכחי: השחרה במכשיר, אישור עותק וחילוץ AI. בדיקת הדפדפן משתמשת בתשובות ספק מבוקרות ומאמתת פרטיות ותהליך; מתאמי הספקים והעלויות נבדקים בשרת. היא אינה בדיקת דיוק של מודל מסחרי.

## בדיקות דפדפן ושרת מקצה לקצה

ההרצה המאוחדת החדשה מיועדת ל־Linux, גם ב־GitHub Actions. נדרשים Docker,
מכולת PostgreSQL בשם `carwise-postgres`, Python 3.12 ו־Playwright:

```bash
python3 -m pip install -r scripts/requirements-test.txt
python3 -m playwright install --with-deps chromium
npm run build
npm run server:build
npm run test:e2e -- --quick
```

`--quick` נשמר לתאימות; במסלול התלושים החדש הכיסוי זהה גם בלעדיו. אפשר לבחור חבילה אחת:

```bash
npm run test:e2e -- --suite fleet
npm run test:e2e -- --suite intent
npm run test:e2e -- --suite innovations --quick
npm run test:e2e -- --suite car-media
npm run verify:judges
npm run verify:payslips
npm run test:e2e -- --suite workspace
```

החיבור נלקח ממשתנה `CARWISE_TEST_CONNECTION`, או מחיבור PostgreSQL המקומי
ב־`.local/appsettings.Development.json`. יש להצביע על שרת בדיקות מקומי בלבד.
אם שם המכולה או משתמש PostgreSQL שונים, מגדירים `CARWISE_TEST_DB_CONTAINER`
ו־`CARWISE_TEST_DB_USER`. למשתמש המסד דרושה הרשאת יצירת מסדי בדיקה.

לכל חבילה נוצר מסד חדש בשם אקראי `carwise_e2e_...`, שמוחלף במחרוזת החיבור
לפני הפעלת השרת. נתוני העובדים סינתטיים. מפתחות ההצפנה זמניים ונפרדים.
המסד נמחק בסיום, גם במקרה כישלון רגיל. אין כתיבה למסד שהוגדר במקור.
לאחר הפסקת מכונה כפויה ייתכן שיידרש לנקות מסד בדיקה שנשאר.

הכיסוי כולל הסתרת החלפות לעובדים, הרשאות תהליך החלפה, הסכמות ואישור קצין
רכב, מסירה ושמירה אחרי הפעלה מחדש; הסכמה למחקר, מחיקת היסטוריית מחקר,
הסתרת קבוצות קטנות; תוצאה מותנית בחוסר מידע, שינוי מדיניות, חודשים חריגים,
השחרה מקומית לפני העלאה, PDF ללא שכבת טקסט מקורית, אישור כל העמודים,
ביטול הסכמה אחרי עריכה, כשל ספק, בחירת שדות תקינים ותצוגה בנייד;
העלאת תמונות רכב, גלריות חוץ ופנים, הגדלה ו־360° בגרירה עם לפחות 12 פריימים.

תוצאות, צילומי מסך ולוגים נשמרים ב־`.local/test-results/` ומוחרגים מ־Git.
סיכום חבילות נמצא ב־`summary.json`. בדיקות מעבדת ההחלטות יוצרות גם
`.local/innovation-verification.json`.

## הרצה אוטומטית ב־GitHub

הקובץ `.github/workflows/tests.yml` מפעיל בדיקות בכל push ל־`main` או `work`,
בכל Pull Request וגם ידנית מתוך Actions. הוא כולל בדיקות שרת וחילוץ,
בנייה ותרחישי דפדפן מול PostgreSQL זמני, כולל בדיקת ההשחרה.
אין צורך להגדיר סודות של הארגון. תוצאות נשמרות כ־Artifacts למשך שבעה ימים.

הרצה מוצלחת אינה אישור אבטחה ואינה מכסה כל תלוש או תרחיש אפשרי. חיבור
Supabase אמיתי, שליחת מיילים ותשובות AI מספק אמיתי אינם נבדקים בהרצה זו.

חזרת השופטים נכללת בהרצה המאוחדת וב־CI. שישה מקרי בדיקה נוספים בודקים שבדיקת המוכנות לענן מזהה קבצים חסרים, חסימת מקור ותגובת HTML שגויה במקום JavaScript. [התסריט והיקף ההוכחה](hackathon-demo.md).

מנוע OCR בדפדפן, קובצי השפה ותלות Tesseract הוסרו מהיישום. [תיעוד תיקון ביטול OCR הקודם](ocr-browser-cancellation-2026-10-22.md) הוא היסטורי.

בדיקת `workspace` מאמתת צ׳אט בתוך העמוד ושימור הודעות אחרי סגירה, חלון דפדפן יחיד, ניווט ניהול מקובץ בלי גלילה אופקית במחשב ובנייד, כניסה מאוחדת והדגמת שחזור מסומנת ללא בקשות רשת. שמירת עובד ותמונות נבדקת בנפרד משינוי מדיניות, כולל אי־שינוי גרסת מדיניות, תיעוד פעולות והישרדות אחרי הפעלה מחדש.

ספק AI ידני: בדיקות שם ואישור יעד, חסימת כתובות פרטיות ותשובות DNS מעורבות, בחירת לקוח HTTP מוגן וניתוב לשלושת המתאמים באמצעות ספק מדומה. בדיקת הדפדפן מוודאת את ״אחר״ ואיפוס אישור היעד כאשר הכתובת משתנה. לא מבוצעת קריאת AI חיצונית בבדיקות.

בדיקת `ai-model` נכללת ב־`test:e2e` ומאמתת שמירה ישירה של קטלוג מודלים, מפתחות וגיבויים, שיוך מודלים לשירותים והפעלת תלושים בלי סיבת שינוי או גרסת מדיניות חדשה. בדיקות השרת מאמתות גם החלפת מפתח בלבד, תעריפים ופרומפטים, סנכרון בין שרתים, מניעת דריסה ושימור AI בשחזור מדיניות.

בדיקת `employee-setup`: הוספת עובד נציג ושמירת הרשאתו בלי גרסת מדיניות, התאמת הרשאה אוטומטית בטופס החשבון, עיסוק חופשי עם כללי זכאות מפורשים, הפרדת נתונים אישיים ממרכז הנציגים ומחיקה מידית של מודל ״אחר״ לפני ואחרי שמירה ללא רענון. יצירת החשבון בדפדפן משתמשת ב־fixture; בדיקות שרת נפרדות מאמתות מניעת עקיפת ההרשאה ושליחת metadata נכון ל־Supabase מדומה.
