# בדיקות אוטומטיות

## הרצה רגילה במחשב (כולל Windows CMD)

```cmd
npm ci
npm test
npm run build
```

נדרשים Node.js 24 ו־.NET SDK 10. הפקודה `npm test` בודקת את חילוץ השדות
בדפדפן ואת בדיקות השרת: חישובי שכר ונטו, זכאות, הרשאות, חשבונות וסיסמאות,
הגדרות, ניתוב AI ועלויות, החלפות רכבים, פרטיות ומעבדת החלטות.
היא אינה דורשת מפתחות Supabase או AI. בבדיקות שירותי צד שלישי נעשה שימוש
בתשובות מבוקרות; הן אינן בדיקת זמינות של הספק האמיתי.

שלוש בדיקות אינטגרציית OCR מדולגות בהרצה הרגילה בכוונה. כדי להריץ אותן:

```cmd
npm run ocr:setup
npm run ocr:verify
npm run ocr:verify:complex
```

נדרש Docker במצב Linux. נבדקים בידוד העובד, התאוששות מקובץ פגום ו־12
מסמכי תלוש סינתטיים מורכבים, מול 84 ערכי שדות צפויים. ההתקנה מורידה
כלים; בזמן עיבוד התלושים לעובד המבודד אין רשת.

## בדיקות דפדפן ושרת מקצה לקצה

ההרצה המאוחדת החדשה מיועדת ל־Linux, גם ב־GitHub Actions. נדרשים Docker,
מכולת PostgreSQL בשם `carwise-postgres`, Python 3.12 ו־Playwright:

```bash
python3 -m pip install -r scripts/requirements-test.txt
python3 -m playwright install --with-deps chromium
npm run build
npm run server:build
npm run test:e2e -- --quick
```

`--quick` בודק שני מסמכי OCR בדפדפן; ללא הדגל נבדקים כל 12 מסמכי הדוגמה.
שאר תרחישי ההרצה זהים. אפשר לבחור חבילה אחת:

```bash
npm run test:e2e -- --suite fleet
npm run test:e2e -- --suite intent
npm run test:e2e -- --suite innovations --quick
npm run test:e2e -- --suite car-media
```

החיבור נלקח ממשתנה `CARWISE_TEST_CONNECTION`, או מחיבור PostgreSQL המקומי
ב־`.local/appsettings.Development.json`. יש להצביע על שרת בדיקות מקומי בלבד.
אם שם המכולה או משתמש PostgreSQL שונים, מגדירים `CARWISE_TEST_DB_CONTAINER`
ו־`CARWISE_TEST_DB_USER`. למשתמש המסד דרושה הרשאת יצירת מסדי בדיקה.

לכל חבילה נוצר מסד חדש בשם אקראי `carwise_e2e_...`, שמוחלף במחרוזת החיבור
לפני הפעלת השרת. נתוני העובדים סינתטיים. מפתחות ההצפנה זמניים ונפרדים.
המסד נמחק בסיום, גם במקרה כישלון רגיל. אין כתיבה למסד שהוגדר במקור.
לאחר הפסקת מכונה כפויה ייתכן שיידרש לנקות מסד בדיקה שנשאר.

הכיסוי כולל הסתרת החלפות לעובדים, הרשאות תהליך החלפה, הסכמות ואישור קצין
רכב, מסירה ושמירה אחרי הפעלה מחדש; הסכמה למחקר, מחיקת היסטוריית מחקר,
הסתרת קבוצות קטנות; תוצאה מותנית בחוסר מידע, שינוי מדיניות, חודשים חריגים,
חילוץ מקומי בדפדפן ללא העלאת המסמך, בחירת כל השדות התקינים ותצוגה בנייד;
העלאת תמונות רכב, גלריות חוץ ופנים, הגדלה ו־360° בגרירה עם לפחות 12 פריימים.

תוצאות, צילומי מסך ולוגים נשמרים ב־`.local/test-results/` ומוחרגים מ־Git.
סיכום חבילות נמצא ב־`summary.json`. בדיקות ה־OCR בדפדפן יוצרות גם
`.local/innovation-verification.json`.

## הרצה אוטומטית ב־GitHub

הקובץ `.github/workflows/tests.yml` מפעיל בדיקות בכל push ל־`main` או `work`,
בכל Pull Request וגם ידנית מתוך Actions. הוא כולל בדיקות שרת וחילוץ,
בנייה, תרחישי דפדפן מול PostgreSQL זמני ובמשימה נפרדת את ה־OCR המבודד.
אין צורך להגדיר סודות של הארגון. תוצאות נשמרות כ־Artifacts למשך שבעה ימים.

הרצה מוצלחת אינה אישור אבטחה ואינה מכסה כל תלוש או תרחיש אפשרי. חיבור
Supabase אמיתי, שליחת מיילים ותשובות AI מספק אמיתי אינם נבדקים בהרצה זו.
