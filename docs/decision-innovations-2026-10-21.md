## משמעות התוצאות

השוואת החודשים משתמשת בכללים הפעילים וברכב הנוכחי כמסגרת משותפת. אין כאן שחזור של הנטו ההיסטורי בתלוש או הסקה של הרכב, העיסוק ומספר הילדים בעבר. רק הבונוס שסומן במפורש כחד־פעמי מוסר מהתרחיש הנוסף; יתר רכיבי אותו חודש נשמרים כפי שאושרו.

מעקב הבחירה אינו תחזית לחקיקה, למחירים או לשנה עתידית. רק מדיניות וגרסת מאגר שהופעלו בניהול משמשות לחישוב. זהות הרכב נשמרת לפי שנת רישום וקודי יצרן/דגם, גם עבור הרכב הנוכחי. החלפת זהות תחת אותו מזהה קטלוג דורשת בחירה מחדש ולא מוצגת כעדכון מס בלבד. חלופה שהוסרה, הפכה ללא זכאית או חסרה בה השתתפות נדרשת לבדיקה; הנטו המעודכן אינו מוצג כסופי. שינוי AI בלבד אינו מוצג כשינוי במדיניות השכר. הנתונים בזמן הבחירה אינם נכתבים מחדש בעקבות עדכון.

ההודעה היא בתוך האתר לעובד מחובר, לא הודעת דוא״ל/Push ולא שירות התראות בזמן שהאתר סגור. החישוב מתבצע לפי דרישה ועם גילוי גרסת ההגדרות הפעילה; לא נוספה משימת רקע שכותבת מחדש את בחירות העובדים.

## שמירה, הרשאות ופרטיות

- חודשים מאושרים ובחירה שמורה נמצאים ב־`carwise_rules.document`, במפתח פרטי `decision:<employeeId>`. אין טבלה או מיגרציית SQL חדשה. נשמרים עד 12 חודשים; אפשר להסיר חודש מההשוואה. כל כתיבה משתמשת בגרסה צפויה כדי למנוע דריסת עריכה מקבילה.
- רשומות ההחלטה אינן חלק מקובץ המדיניות הפעיל או מגרסאות הניהול. מנגנון ההרשאות הקיים מאפשר לעובד רק את נתוניו; מנהל מורשה לצפות/לפעול לעובד. אין גישה ישירה למסד מהדפדפן. טבלת הכללים כבר חסומה לגישה ציבורית ב־RLS.
- אין שמירת מסמך, תמונה, שם קובץ, טקסט גולמי או קואורדינטות בסיכומי החודשים/הבחירה. פרופיל הבחירה מצומצם: השם, שדה השאלה ושם המודל הנוכחי אינם מועתקים אליו. נתוני שכר ועיסוק נשארים רגישים, גם ללא מסמך או שם.
- קואורדינטות הסימון זמניות. במסלול השרת העובד המבודד רשאי להחזיר רק מזהי שדות מוכרים, עד שלוש תיבות לשדה, עמוד 0–5, סוג תיבה סגור ומספרים סופיים בתחום העמוד. השרת דוחה מטא־דאטה לא תקין; אין ציטוטים או טקסט חופשי בפרוטוקול.
- במסלול המכשיר קובצי השפות נמצאים בריפו, גיבובם מאומת בבנייה, ועותק ה־Worker וה־WASM מועתק מחבילות npm נעולות. גיבובי השפות אומתו גם מול `tessdata_fast` הרשמי. אין CDN בזמן עבודה ואין אחסון תוצאות/מסמכים ב־IndexedDB או localStorage. Worker החילוץ מסתיים בסיום/ביטול; התצוגה והקובץ משתחררים ביציאה/הסרה. אין הבטחה לאיפוס כל עותק בזיכרון מערכת ההפעלה.
- גם פעולות המעבדה והחודשים עוברות אימות והרשאה בשרת. אין שימוש בספק AI בתכונות אלה ואין חיוב טוקנים עבורן. מדיניות ספק השיחה נפרדת ממסלול המסמכים.
- הסרת חודש מוחקת אותו מרשומת ההשוואה הנוכחית; היא אינה מוחקת אוטומטית גיבויים או WAL. תוכנית שימור ארגונית, MFA ושאר פערי [תוכנית האבטחה](security-roadmap.md) נשארים נדרשים לפני פיילוט עם נתוני אמת.

## הפעלה

עצרו את השרת. מתיקיית הפרויקט:

```sh
git pull origin main
npm ci
npm run build
npm start
```

`npm ci` נדרש לתלות WebAssembly החדשה. `prebuild` מכין Worker ו־WASM מקומיים ובודק את גיבובי קובצי השפה, ללא הורדה של מודלים בזמן הבנייה. לפיתוח עם Vite אותה הכנה פועלת ב־`predev`.

בניהול → **פרומפטים ותלושים**, הפעילו ושמרו חילוץ. ההגדרות השמורות של שפות, עמודים, סף ביטחון וזמן משמשות גם למסלול המכשיר. למסלול הזה לא דרוש Docker או מפתח AI. חילוץ עברי משתמש גם במודל האנגלי לקריאת ספרות; קריאה עברית משלימה מתקנת תוויות בלבד ולא מחליפה מספרים.

כדי להשתמש בחילוץ בשרת ולקבל גם ממנו מיקומי מקור, בנו מחדש את העובד המבודד:

```sh
npm run ocr:setup
npm run ocr:verify
```

שרת ישן של העובד עדיין יכול להחזיר שדות בלי מיקומים; הממשק לא ימציא מיקומים עבורם. יש לפרוס את קוד השרת, הממשק והעובד בגרסאות התואמות.

## בדיקות וראיות

```sh
npm run test:browser-payroll
CARWISE_VERIFY_OCR=true CARWISE_VERIFY_COMPLEX_OCR=true npm test
python3 scripts/smoke.py
python3 scripts/supabase-smoke.py
npm run verify:innovations
```

סקריפטי Python דורשים סביבת בדיקות מקומית עם PostgreSQL/Docker, הגדרות פיתוח, Playwright ו־Chromium לפי בדיקות הפרויקט. הם יוצרים מסדים נפרדים, משתמשים בנתונים סינתטיים בלבד ומסירים את מסדי הבדיקה; אינם בודקים את פרויקט Supabase האמיתי של המשתמשת. סקריפטי האינטגרציה משתמשים בקבוצות תהליכים של POSIX ומיועדים לסביבת Linux/WSL. ב־CMD של Windows משתמשים בפקודות npm הרגילות להתקנה, בנייה והפעלה; בדיקות Node ו־.NET אינן תלויות בסקריפט Python זה.

- 219 בדיקות .NET עברו ללא דילוגים, כולל הרצת Docker אמיתית, 12 התלושים המקוריים וגבולות נקודת האיזון. נוספה גם בדיקת בטיחות עצמאית למחלץ TypeScript.
- בדיקות PostgreSQL ו־Supabase/PostgREST עברו עם אימות חודשי שכר, התנגשויות גרסה, הסרת חודש, שינוי מדיניות ושינוי מאגר רשמי לאחר שמירת בחירה. נבדקו גם הקמה ראשונית והפרדת הרשאות לכל נקודות ה־API החדשות.
- בדיקת הדפדפן משתמשת בכל 12 הקבצים המקוריים: 3 PDF טקסטואליים, 3 PDF סרוקים, 3 PNG ו־3 JPEG. כל 84 השדות תאמו לנתוני האמת. ניטור הבקשות זיהה **0 העלאות מסמך ו־0 בקשות לאתר חיצוני**, ונבדקו מיקומי מקור, אישורי שדות/חודש/בונוס, שמירה ורענון, תרשים נגיש למיקוד, מובייל וביטול ללא מעבר לשרת.
- אלו מסמכים סינתטיים ספורים ומדידת Chromium במחשב הבדיקה, לא מדד דיוק לכל תוכנות השכר ולא SLA למכשירים ניידים. קובץ מטושטש, מסובב או לא מוכר עשוי לדרוש תיקון/הזנה ידניים. יש לבדוק מדגם ארגוני מאושר ולבצע הערכת ביצועים על מכשירי היעד.
