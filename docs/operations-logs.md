# לוגי מערכת

בניהול המערכת → מערכת ותיעוד → **לוגי מערכת** אפשר לחפש אירועים, לסנן לפי רמת חומרה מינימלית, רכיב וטווח זמן, לטעון רשומות קודמות, להפעיל רענון כל עשר שניות ולייצא את התוצאה ל־JSONL. זמני האירועים מוצגים בשעון ישראל; מסנני התאריכים משתמשים בשעון המכשיר.

הגישה לקריאה ולייצוא דורשת הרשאת מנהל בצד השרת. עובד או נציג אינם מורשים לגשת לנקודות הקצה. הלשונית אינה משנה גרסת מדיניות או הגדרות AI.

## מה נאסף

- הודעות `ILogger` של האפליקציה והספריות, בהתאם למסנני `Logging:LogLevel` של השרת. הודעות Console קיימות ממשיכות להופיע גם באירוח. פלט שרירותי שנכתב ישירות ל־stdout/stderr אינו מיובא.
- סיום בקשות API: תבנית הנתיב, שיטת HTTP, סטטוס, משך ומזהה מעקב. תבנית כמו `/api/employee/{id}` אינה מכילה את מזהה העובד בפועל. הנתיב הגולמי, Query String, כותרות וגוף הבקשה אינם נרשמים. תגובת השרת כוללת `X-Request-ID` לאיתור האירוע.
- ניסיונות קריאה לספקי AI: פעולה, ספק, מודל, מספר ניסיון, משך, סטטוס ספק וקוד תקלה. אין מפתח, פרומפט, מסמך או תשובת המודל. זהו יומן תפעולי; פירוט טוקנים ואומדני עלויות נשאר ביומן שימוש ה־AI הקיים.

בקשות לבריאות השרת, למצב הריצה וללוגים עצמם אינן יוצרות אירוע סיום בקשה, כדי למנוע הצפה מרענונים. קריאה שלא הגיעה לשרת לא תופיע ביומן. ברירת המחדל אוספת Information ומעלה, ול־Microsoft.AspNetCore רמת Warning ומעלה. בחירת Debug בממשק אינה משנה את מסנני האיסוף בשרת.

## פרטיות

ספק הלוגים מרנדר רק שדות אבחון ברשימת היתר. ערכים של שדות אחרים מושחרים; הודעות חריגה גולמיות, scopes ואובייקטים שרירותיים אינם נשמרים. הודעות ללא תבנית מובנית מושמטות, למעט הודעות קבועות מאושרות. כתובות URL מצטמצמות לשם השרת, ודפוסים מוכרים של מפתחות, credentials ודוא״ל מושחרים כהגנה נוספת.

אין מדובר במנגנון שמזהה כל מידע אישי בכל טקסט אפשרי. בהוספת לוגים בקוד חייבים להשתמש בתבנית קבועה ובשדות אבחון בלבד; אין לשלב תוכן משתמש, שכר, תלוש או סודות בתוך מחרוזת התבנית או בתוך שדה מאושר. מסד נתוני המשתמשים ויומן שיחות אינם מקור לטאב זה. הרשאת מנהל אינה סיבה להכניס מסמכי שכר ליומן.

## שמירה ותפעול

בכל מופע שרת נשמרות עד **5,000 רשומות ועד שבעה ימים**, לפי המוקדם. הקריאה והכתיבה ליומן נעשות בזיכרון; עובד רקע שומר צילום אטומי כל שתי שניות בקובץ:

```text
<CARWISE_KEYRING_DIR>/application-logs/system-logs.json
```

ללא המשתנה, התיקייה נמצאת תחת `.local/admin-keys`. הרשאות התיקייה והקובץ ב־Linux מוגבלות לבעל התהליך (700 ו־600). השמירה משתמשת בדיסק הקבוע הקיים של המפתחות; אין מיגרציית DB או צורך להעלות מסד חדש. ב־Railway יש לוודא ש־`CARWISE_KEYRING_DIR` נמצא ב־Volume הקבוע. ללא דיסק קבוע, החלפת container עשויה למחוק את היומן. נפילה פתאומית עשויה לאבד את האירועים מאז הצילום האחרון.

בתקלה בשמירת הקובץ האפליקציה ממשיכה לעבוד והטאב מציג אזהרה על מצב זיכרון בלבד. עובד הרקע מנסה שוב. הקובץ אינו מוצפן בנפרד; יש להגן על הדיסק והגיבויים בתשתית. אין לשמור אותו ב־Git.

היומן כולל אירועים שנאספו לאחר פריסת התוספת ואירועים שנשמרו בקובץ זה לפני הפעלה מחדש. הוא אינו מושך לוגים היסטוריים, build logs או לוגי תשתית מ־Railway, Supabase או מערכת ההפעלה. הוא מיועד למופע שרת יחיד; הפעלת כמה replicas דורשת איסוף מרכזי ייעודי. אין לתת לכמה תהליכים לכתוב לאותו קובץ snapshot.

## בדיקות

`npm test` כולל בדיקות הפרדה בין הרשאות מנהל/נציג/עובד/אנונימי, השחרת מידע, שמירה ושחזור, סינון, דפדוף, מגבלות נפח והתאוששות מכשל דיסק. `npm run test:e2e -- --quick --suite logs` בודק בקשה אמיתית, קישור למזהה המעקב, מסך הניהול, ייצוא, רענון, מובייל ושחזור לאחר הפעלה מחדש מול PostgreSQL זמני.
